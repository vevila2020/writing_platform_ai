# 连续多章

用于作者明确要求多章、日更批次或指定章节区间。“继续写”默认只接下一章；“按这个来”沿用上一轮对象。未给数量的日更先建议范围，已给范围直接执行，不设置固定每轮上限。

## 批次开始

1. 核对实际正文、当前细纲和 `prepare_advance` 返回的处境。已有书稿首次启用时按追踪参考初始化；不要手改生成视图来消除冲突。
2. 读本批所属卷/章组的职责和各章细纲。缺细纲时在已授权方向内补齐并检查；会改变主线或人物决定时先列出具体选择。
3. 按 `context-and-recall.md` 准备本章材料。久别人物重新出现时读取其完整状态和相关原文。

## 逐章闭环

每章完整执行 `workflow-chapter.md`：细纲检查 → 准备 → 写作 → 确定性检查与只读审稿 → 修订 → 再准备 → 提交 → 读回。

- 必须串行；上一章成功提交后才开始下一章。审稿者只读，不并发写章。
- 复用适用的 `novel-craft` 小节；跨章承接需要时补读 `long-form.md`。不寻找无来源的“独立技法文件”。
- 遇到未解决硬伤、状态冲突、需要作者决定或用户取消时，停止后续章并说明已完成的范围；已保存草稿与已提交章节要分清。
- 中断后从实际准备结果和产品会话恢复继续。相同成功提交可安全重试；正文再改过就重新准备，不重放旧更新。

## 批末只核对跨章问题

- 章组承诺是否兑现，人物的选择是否产生收益与后果，信息是否按时揭示。
- 本批伏笔新增、推进、解决是否与最终正文及底账一致；不为批末汇报重新全量审计历史。
- 冲突和回报是否重复；下一段应怎样换压力、选择或兑现方式。
- 显示标题可建议改善；不为标题重名自动重命名文件，章节路径已绑定连续性记录。

批末修订任何已提交正文，都按改稿流程再次检查和提交。只修改授权范围，后文影响记录为明确冲突，不静默改相邻章。

## 汇报

说明完成的章节、总字数、每章一句变化、必要的偏离与未决项。范围完成后停，不追加“确认后我才继续”等已获授权的门槛；也不自行扩大下一批。卷末说明承诺怎样兑现、下一卷是否已有计划。
