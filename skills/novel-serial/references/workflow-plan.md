# 规划工作流：开书、卷纲、章组、细纲

本文件用于 `novel-serial` 的规划模式。只做作者要求的层级，交付后停；不自动从大纲展开到细纲，也不自动从细纲展开到正文。

## 共同的确认点

规划按层级推进，只问会改变本阶段交付的缺口，每次集中 2–3 个具体问题，给推荐与理由。已有材料能回答的不再问；作者已授权完整开书时连续完成已确定阶段，仅在真实创作分歧处交接。

1. **开书**：题材定位、核心卖点、目标读者、主角目标与阻碍、核心体验、篇幅与平台。结论写回 `ideas.md`，经作者确认后更新 `CREATOR.md` 和 `setting/outline.md`。
2. **卷纲**：本卷承诺、阻碍、兑现、余波、关键转折、伏笔埋设与回收、章组划分。写进 `setting/outline.md` 或当前章组计划。
3. **章组计划**：只规划下一组连续章节，写清组目标、承接、逐章职责、爽点/微兑现、章尾期待。写入 `setting/chapter-groups/groupXX-<short-objective>.md`。
4. **细纲**：一章一份，写清本章目标情绪、主角目标/关键选择、场景推进、情节点、章尾钩子。写入 `setting/chapter-plans/<chapter-order>-<slug>.md`。

规划阶段不写正文，不初始化 `tracking.md`，不提交逐章状态。作者说“继续/按这个来”只表示确认当前层级，不扩大范围。

## 开书

### 先读

- `ideas.md`：作者已有的题材、卖点、方向和未决问题。
- `CREATOR.md`：章节长度、禁止内容、文风、视角、对话要求等长期约束。
- 当前 Lore：已存在的角色、地点、势力、规则和世界事实。

### 方向：先证明故事为什么值得追

- 主角是谁、此刻想要什么、被什么挡住、失败会失去什么。
- 读者主要获得哪种体验：成长、关系、解谜、求生、复仇/证明、幽默、悲伤中的哪一种。
- 核心设定如何改变主角的选择；删掉它故事是否还成立。
- 平台、类型与读者预期以作者选择和有来源的研究为依据，不把平台标签当硬规则。按 `context-and-recall.md` 召回相关情绪、节奏或读者承诺模块；没有研究就明确是假设。

### 设定：让核心机制产生选择与代价

- 方向交付包含一句话故事、目标读者、核心体验、主角处境与开篇方案。作者确认或已明确指定后写回 `ideas.md`；长期偏好只记录到 `CREATOR.md`。
- 固化开篇必须的主角目标、对手诉求、核心规则的机会/代价/限制、重要关系张力；稳定事实通过 `write_lore_items` 分批写入 Lore。不一次铺满所有地图、配角和升级层级。
- 使用 `novel-craft` 的人物与规则参考；题材专属判断复用本书已有的 `genre-*` Skill。保留作者未决定项，不把备选方案全部写成设定。

### 结构与首批细纲：从承诺走向兑现

- 在方向与核心设定成立后生成全书粗结构，再细化首卷与眼前章组。远期保留转折、升级边界与兑现位置，避免提前精排全书每章。
- 章组按“本章职责 → 人物选择 → 小回报 → 新期待”分配，不用单纯事件清单代替情绪推进。
- 首批细纲覆盖作者要求的范围；先检查每章的目标情绪、关键选择、信息边界与章尾，再交给写作。未授权正文时到此停。
- 开书规划不预填已发生的进度或人物状态，不直接创建三个生成视图。第一章最终审稿后通过 `commit_advance` 建立底账；已有正文采用初始化流程。

## 全书大纲

`setting/outline.md` 只写计划和长期结构，不写已经完成的进度。

```text
主线问题：
主角起点（缺口 / 处境 / 错误认知）：
预期终点（能力 / 认知 / 关系 / 处境）：
核心对抗（谁、争什么、为什么不能退）：
关键转折：
  1. 事件 → 选择 → 局势变化 → 新目标
伏笔与兑现：
  伏笔内容：埋设位置：预计回收位置：兑现时改变什么：
终局底牌（只能用一次）：最早解锁卷 / 阶段：
升级台阶（等级 / 地图 / 势力层数）：每档大致停留：
核心爽点：
  期待：铺垫：兑现：余波：
```

检查：

- 每个转折是否由人物选择触发；删掉它，后文是否还能成立。
- 终局底牌是否被提前使用，升级线是否提前触顶。
- 伏笔是否标注埋设和兑现阶段；决定放弃的标为弃用，不悬空。
- 中段是否出现新的问题与解法；结局是否能回应开篇承诺。

## 卷纲

一卷至少回答四件事：读者期待什么、受到什么阻碍、兑现什么、留下什么持续影响。

```text
本卷承诺：
本卷阻碍：
本卷兑现：
本卷余波：
关键事件（按因果排列，3–6 个）：
小回报位置：
主要兑现位置：
章组职责（只细化即将写的部分）：
承接前卷（人物处境、未解决后果）：
伏笔：埋设 / 推进 / 回收
```

检查：

- 删掉本卷，全书主线是否仍然完整；如果完整，说明它只是填充。
- 小回报是否出现在主要兑现之前。
- 余波是否改变人物处境或关系，而不只是宣布下一场危机。
- 是否围绕本卷主要矛盾取舍事件，而不是把无关冒险串成流水账。

## 章组计划

只规划下一组连续章节，建议 3–8 章，按叙事单元决定，不机械凑数。文件写入 `setting/chapter-groups/groupXX-<short-objective>.md`，保持短、可扫读、易改。

```text
本章组目标：
承接的旧期待：
组内冲突曲线：
每章：
  第 N 章：目标 / 必须发生 / 不得越界 / 章末新期待
本章组末兑现：
允许的过渡章（可以低压，但不能整章无收获）：
需要作者决定的问题：
```

章组计划不是细纲。它只决定“这组章节各自承担什么功能”，具体场景、情节点和台词留给细纲。

## 细纲

细纲是正文写作的章节蓝图，写给作者和写手看。一章一份，使用 `skill://novel-serial/references/chapter-plan-template.md` 的模板。

写细纲前：

1. 读 `setting/outline.md` 的长期方向和当前章组计划，确定本章在组内的职责。
2. 已有正文先 `prepare_advance`，核对当前位置、活跃伏笔、下一章承诺和连贯性风险；无正文时使用已确认设定，不编造历史。
3. 读本章会出场角色的 Lore 条目（`query_lore_items` + `detail=full`），确认身份、能力边界和已知信息。
4. 读最近两章正文，确认时间、地点、人物状态和上一章留下的钩子。

细纲至少写清：

- 核心事件：本章一句话发生了什么。
- 字数目标或作者给的字数范围。
- 所属章组/剧情段，以及本章在该段里承担哪一步。
- 目标情绪：读者从什么情绪走到什么情绪，不写“热血”“悲伤”这类单词。
- 主角目标/关键选择：本章要什么，必须做什么判断或取舍。
- 章首钩子、爽点/微兑现、章尾钩子：写具体场面或那句话，不写类型名。
- 场景推进：起因、发展、转折、高潮、结尾。
- 情节点表：谁做了什么、作用是什么；点数按需要定，不按目标字数反推。
- 信息边界：谁知道什么、读者知道什么、主角误判什么。
- 本章不能说破的事（可选）、必须原样出现的原话（可选）。

细纲完成后，向作者汇报“本章会写什么、停在哪里、需要作者定什么”，等作者确认或直接进入正文，取决于作者本轮是否已经明确授权写正文。

细纲落盘后运行 `check_writing`：`{"action":"plan","path":"<细纲路径>"}`。有 blocking（缺核心事件、目标情绪、主角目标/关键选择、章尾钩子）时先补齐，再进入正文。

## 缺少规划材料时

- 有正文却没有细纲：先按正文反推本章细纲，标出不确定项，再继续；不要凭空补出正文没写过的主线。
- 有细纲却没有章组计划：先补本章所属章组的短计划，或在细纲里写明本章在卷纲中的位置。
- 实际正文严重偏离大纲：先问作者是更新大纲，还是用后续章节拉回主线；不要一边写一边悄悄改大纲。
