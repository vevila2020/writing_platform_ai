# 单章写作

只处理作者授权的这一章。完成意味着最终正文、检查、审稿和连续性提交一致。

## 写前准备

1. 从实际目录和章组确定本章，不只依赖进度摘要。尊重卷/章/节结构，正文落在最深一级。
2. 读本章细纲；缺少时按 `chapter-plan-template.md` 补出已授权内容。运行 `check_writing action=plan`，实际补齐所有 blocking 字段。细纲是剧情蓝图，不能靠正文擅自填入新主线。
3. 调用 `prepare_advance`，传本章 `path` 和细纲 `plan_path`。前章未提交或后文冲突未解决时先修复。首次使用的旧书按 `tracking-template.md` 初始化。
4. 按 `context-and-recall.md` 组装本章材料：CREATOR 适用约束、细纲、相关卷/章组段落、上一章全文、再上一章相关段、活跃事实、必要 Lore、创作技法和一份适用研究。不整库加载。
5. 在内部回答：读者承接什么期待；主角做什么有代价的选择；本章实际兑现什么；结尾留下什么具体后果。回答不了先修细纲。

## 写正文

- 用 `write` 新建或整章重写，`edit` 局部修改。定位文本来自最新读取，不带行号；失败就重读和修正。
- 从处境、动作、对话和选择推进。收益落实给实际促成结果的人，不只写旁人震惊或旁白宣布。
- 章末落到动作、画面、台词、选择或后果，不写“下一章将……”预告。
- 普通细节不额外登记；复用人物、伏笔、关系、承诺、硬数字在提交中登记；新增主线、规则或提前揭晓先取得作者选择。
- 可以调整执行和台词，不能改掉细纲已定结果或人物决定；不靠临时能力、注水或占位句填满。

## 检查、审稿、修订

1. `check_writing action=chapter`，传真实细纲。本轮字数范围用 `word_min` / `word_max`。
2. 按 `review-rubric.md` 只读审稿。本 Skill 要求委派可用时通过实际协议调用一个 `general-purpose`，等到结果后再处理；不可用或作者要求独立完成时自审。
3. 事实对照前文、Lore、人物所知与细纲；表达问题保留作者声音，只做必要修改。审稿者不改文件。
4. 修订后重跑相关检查；没有变化不重复全套检查。改变事实必须重核连续性。

## 提交

1. 最终修改后再次 `prepare_advance`，取得对应此版正文、细纲与状态的 `base_revision`。
2. 按 `tracking-template.md`，一次 `commit_advance action=commit` 提交摘要、变化人物、伏笔、信息边界与下一章工作集。
3. 不手改底账和生成视图。撤下约束、风险或承诺时在 `retired_context` 写原文及原因；不能静默丢失。活跃集合移除只退出当前上下文，完整事实仍在底账。
4. 陈旧版本被拒绝时重新准备、读差异并合并，不原样反复重试；响应丢失可以重试相同请求，不重复加章。
5. 字数带外先修订或询问作者；只有作者接受当前长度才填 `length_decision=author_accepted`，硬伤仍须修。
6. 确认回执成功，读回生成台账检查故事语义再汇报。未提交只算草稿，不自动写下一章。

旧章改稿按修订参考处理。摘要对应该章；人物与信息快照始终表示最新已写位置，不退回旧章当时状态。
