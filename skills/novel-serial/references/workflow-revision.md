# 改稿与重写

用于作者说“修改第 X 章”“回炉”“重写第 X 章”“这段不对”，对象是已写正文。只改细纲不进此流程；只润色表达优先用 `novel-deslop`。

## 先分诊

| 作者的说法 | 先判断 | 处理 |
| --- | --- | --- |
| 读不下去、太平 | 开篇是否进入具体处境，期待是否建立 | 补具体压力或选择，删前置说明；必要时重写场景 |
| 人物动机不成立 | 目标是否具体，选择是否有代价 | 补一次有取舍的选择，交代底线 |
| 因果牵强 | 结果是否来自前文能力/准备/选择 | 补铺垫或改变结果来源，不硬加解释 |
| 前后矛盾 | 谁知道什么、何时发生 | 以已确认正文和作者确认为准，修错误的一边 |
| 冲突重复 | 问题与解法是否变化 | 换阻碍类型、代价或兑现方式 |
| 结尾不满足 | 是否回应本章/本卷承诺 | 回到期待和人物选择，补兑现，不改句子 |
| 只是 AI 味重 | 表达层问题 | 加载 `novel-deslop`，不改剧情事实 |

改稿前先读：本章全文、相邻章节、本章细纲、`progress.md`、`character-states.md`、`tracking.md`、相关 Lore。作者只给片段时，直接在对话里改，不写工作区文件。

## 修改原则

- 作者本轮要求最高优先；只改点名章，不顺手改相邻章节、大纲或 Lore。
- 先定位原因，再动文字；好句子救不了缺少铺垫的结局。
- 保留有效段落、人物声音、作者有意文风和留白。
- 能局部 `edit` 就不整章 `write`；整章重写只在结构确实不成立时使用。
- 不新增细纲外的主线事件；需要新增时按“先问作者”处理。
- 修改后检查对后文的影响：伏笔、人物状态、关系、时间线、硬数字。

## 改稿后的状态同步

- 任何落盘的正文修改都会改变版本：检查最终正文，再 `prepare_advance` → `commit_advance` 更新检查点。纯措辞修改保持原摘要、事实与当前工作集合，只提交新的正文版本，不虚构状态变化。
- 改变剧情事实、人物状态、关系、伏笔或时间线：提交实际变化；状态代表整本书当前进展的末端，不把全书当前位置倒退到被修改的旧章。
- 受影响的后文已写时，明确列出文件和原因，提交为 `unresolved`；只修授权章节。未解决前不续写新章，作者授权修后文后逐章消除冲突。
- 导入旧书的历史章修订，需传 `baseline_progress`，原样保留仍有效的历史进度，修正已失效部分；纯措辞修改可原样传回。它不是要求重新推断整本书。
- 过时摘要必须以最终正文和作者确认为准，不让旧状态约束重写。不要分别手改三个生成视图；Lore 只在确认的稳定事实改变时更新。
- `outline.md` 只有作者明确要求结构调整时才改。

## 重写整章

1. 读本章细纲；细纲本身有问题时先修细纲，再写正文。
2. 读相邻章节和台账，确认本章的进入状态和退出状态。
3. 按 `skill://novel-serial/references/workflow-chapter.md` 写正文，不复制旧版本的句子，除非作者要求保留。
4. 写后按 `skill://novel-serial/references/continuity-and-quality.md` 检查；先运行 `check_writing`（`action=chapter`），必须处理项清零。
5. 再准备并提交，读回确认；说明改了哪些事实、哪些后文章节有待修正。检查或提交失败时如实标记草稿未完成。

## 不要

- 不要用润色掩盖结构问题；剧情不成立时回到细纲或大纲。
- 不要在改稿时改变视角、信息边界或人物关系，除非作者明确要求。
- 不要把“改得像人写的”变成新增事件、微动作或新设定。
- 不要绕过 `edit` / `write` 直接改文件。
