# 研究报告格式

报告保存到工作区 `setting/research/YYYY-MM-DD-<slug>.md`。只在作者要求保存或当前流程要求落库时写入；否则直接在对话中回答。

## 文件命名

- 日期用抓取/写作当天：`2026-11-04-qidian-xuanhuan-monthly.md`。
- slug 用小写英文和连字符，能看出平台、题材、报告类型。
- 同一天同一主题多份报告时加序号或更具体的限定词。

## 结构

```markdown
# <标题>

## 元信息

- 类型：扫榜 / 拆文 / 题材判断 / 其他
- 平台：
- 榜单或来源：
- 抓取日期：
- 样本量：
- 置信度：高 / 中 / 低（说明原因）

## 结论摘要

3–5 条，直接回答问题。

## 样本与方法

- 查询了什么、抓取了哪些页面
- 实际读到多少本/多少章
- 未能获取的部分

## 关键发现

每条发现附证据：

- **发现**：
- **证据**：<短句引用或数据> — [来源标题](URL)（抓取日期）
- **性质**：页面可见事实 / 推断

## 可复用模式

1. 模式：
   - 适用条件：
   - 落地建议：
   - 不可照搬的部分：

## 与当前作品的结合点

最多 3 条，具体到章节、人物或设定层；只给建议，不改文件。

## 风险与未知

- 样本限制：
- 数据缺口：
- 平台或政策风险：
- 需要作者补充的材料：

## 下一步

可选的后续动作：补样本、换平台、拆某本书、验证某个假设。
```

## 写法要求

- 元信息必填；抓取日期不能省略，榜单类报告必须写明「截至某日」。
- 结论与证据分开，推断要标注。
- 数据缺失写「未获取」，不写 0、不估算。
- 链接使用实际抓取页面的最终 URL；不引用搜索结果页、缓存页或转载页。
- 短句引用，不复制大段正文。
- 报告面向作者本人，语言简洁，不用营销腔。
- 报告是外部研究资料，不自动成为故事设定；引用时说明这一点。

## 与工作区的关系

- 只写 `setting/research/`，不写 `chapters/`、`setting/lore/` 或 `.inkdock/`。
- 报告里的人物/地点建议不直接进入 Lore；需要时走现有预览 → 计划 → 应用流程。
- 写作 Agent 会在工作区索引里看到最近的研究报告路径，需要时按需读取。
