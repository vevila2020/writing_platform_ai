# 拆文

拆文的目标不是复述剧情，而是找出「这本书靠什么留住读者」以及「哪些做法能迁移到作者自己的作品」。

## 输入

- 作者提供的书名、链接、正文片段优先。
- 只有书名时，先用公开来源找到作品页和可读章节；读不到正文就只做「简介 + 标签 + 可见章节标题」层面的拆解，并说明限制。
- 只拆作者指定的范围（前三章、某一卷、某一类型场景），不默认扩到全书。

## 三轮拆解

### 第一轮：前三章逐章表

| 项目 | 记录 |
| --- | --- |
| 本章钩子 | 开篇第一段/第一个场景抛出了什么 |
| 信息投放 | 读者知道了什么、还不知道什么 |
| 主角目标 | 这一章他想要什么、被什么挡住 |
| 爽点/情绪点 | 兑现了什么（打脸、升级、被认可、心疼、解谜） |
| 章尾悬念 | 下一章读者为什么要点开 |
| 读者问题 | 读完这一章，读者最想知道什么 |

结论写成「第 1 章建立 X，第 2 章兑现 Y，第 3 章扩大为 Z」这样的链条，不要逐段复述。

### 第二轮：故事引擎

| 维度 | 要回答的问题 |
| --- | --- |
| 核心承诺 | 读者点开这本书，期待持续得到什么 |
| 主角目标 | 长线目标是否具体、可阶段化 |
| 主要阻力 | 来自人、制度、环境还是自身 |
| 金手指/核心优势 | 独特在哪、限制和代价是什么 |
| 关系结构 | 谁提供助力、谁制造对照、谁承担情感、谁是对手 |
| 对手层级 | 对手是否随主角成长而升级 |
| 升级阶梯 | 能力、地位、资源如何分段变化 |
| 节奏 | 小兑现/大兑现的间隔，章尾钩子的类型分布 |

### 第三轮：可迁移模式

分三类写：

1. **可直接迁移**：结构、节奏、信息投放方式、场景设计。
2. **需要改造**：依赖特定题材或平台的模式，迁移时要换载体。
3. **不可复制**：专有设定、独特人名地名、标志性桥段、作者个人文风。照搬会变成抄袭或水土不服。

每条迁移建议都要写清「用在作者作品的哪一部分、怎么改」。

## 引用规则

- 只用短句作为证据（一般不超过一两句），标明来自第几章或哪个页面。
- 不复刻大段正文、不逐段改写原文。
- 分析判断与原文事实分开：原文是「原文写 X」，判断是「这起到 Y 作用」。

## 输出结构

1. **一句话结论**：这本书的核心吸引力是什么。
2. **前三章表**。
3. **故事引擎图**：承诺 → 目标 → 阻力 → 优势 → 关系 → 对手 → 阶梯。
4. **可迁移模式**：分三类，每条附落地建议。
5. **风险与限制**：只读到多少内容、哪些判断是推断。
6. **与当前作品的结合点**：最多 3 条，具体到章节或设定层，不直接改写。

## 常见错误

- 把剧情梗概当拆解。
- 只夸不拆，没有可执行结论。
- 把「这本书火了」当成「这套写法一定有效」。
- 忽略平台差异，用长篇标准评价短篇。
- 迁移建议过于抽象（「加强节奏」），没有落到具体场景。
