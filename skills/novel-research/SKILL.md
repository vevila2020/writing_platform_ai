# 扫榜 / 拆文 / 市场研究

把「最近什么书火」「这本书为什么火」这类问题，变成有来源、有时间、有边界的回答。研究结论用于判断，不直接改正文、大纲或设定。

## 边界

- 只做研究与拆解，不写正文、不改章节、不动大纲和 Lore。需要落库时只写 `setting/research/` 下的报告。
- 不绕过登录、付费墙、验证码或反爬；不批量抓取；不调用未提供的平台接口。
- 不编造榜单排名、收藏数、评论数、在读、追读、付费数据。看不到的字段写「未获取」，不估算、不用其他书的数据代替。
- 区分三类信息：**页面可见事实**（书名、作者、排名、标签、简介、可见字数）、**推断**（结构判断、读者预期）、**未知**（真实营收、完读率、后台数据）。
- 作者提供的链接、书名、正文片段优先于自行搜索。用户没给作品时，先问清平台和范围，不要猜。

## 直接问答

用户可以只问一句「最近起点玄幻什么书火」或「番茄都市榜前十有什么共同点」。按下面的顺序处理：

1. **界定问题**：需要哪些平台、哪个频道/分类、哪类榜单（畅销/新书/推荐/月票/金榜等）、什么时间窗口。用户没说时，选一个有代表性的默认范围，并在回答里写明假设。
2. **确认工具**：需要联网取证时加载 `web-research`，遵守其中关于搜索角度、取证、引用和失败处理的规定；没有 `web_search` / `web_fetch` 时直接说明无法联网，请作者粘贴页面或提供链接。
3. **找公开来源**：用 `web_search` 找到当前公开的榜单页、分类页或作品页，再用 `web_fetch` 读取。优先官方榜单与作品页，其次是有明确来源和日期的行业报道。搜索结果的摘要只能作为线索，不能当作数据。
4. **记录可核验字段**：平台、榜单名、页面 URL、抓取日期、排名、书名、作者、题材标签、可见数据。抓取不到就留空并标注。
5. **回答**：先给结论，再给样本列表和来源，最后说明样本量、时间窗口与缺口。榜单会变，必须写「截至某日」。

联网细节、平台差异和失败处理见 `skill://novel-research/references/platforms.md`；扫榜字段与分析方法见 `skill://novel-research/references/market-scan.md`。

## 拆文

作者给出书名、链接或正文片段时，按三轮拆解：

1. **前三章逐章表**：每章的钩子、信息投放、爽点/情绪点、章尾悬念、读者此刻想知道什么。
2. **故事引擎**：核心承诺、主角目标、主要阻力、金手指或核心优势、关系结构、对手层级、升级阶梯。
3. **可迁移模式**：哪些做法能用到作者自己的作品，哪些依赖专有设定、人名或独特桥段而不该照搬。

引用原文只取短句作证据，不复制大段正文。详细模板见 `skill://novel-research/references/deconstruct.md`。

## 报告与落库

- 只在作者要求保存，或当前流程明确要写研究文件时落库；路径为 `setting/research/YYYY-MM-DD-<slug>.md`。
- 报告结构：元信息（作品/平台/来源/日期/样本量/置信度）→ 结论摘要 → 样本与方法 → 关键发现（带证据）→ 可复用模式 → 与当前作品的结合点 → 风险与未知 → 下一步。
- 只写研究结论，不把建议直接改成大纲或人物状态；需要应用时交回当前写作流程，走确认和预览。
- 报告是参考资料，不是故事设定。后续引用时说明它是外部研究。

完整格式见 `skill://novel-research/references/report-format.md`。

## 回答习惯

- 用作者的语言，先回答问题，再给依据。
- 每个关键事实后附来源链接和日期；没有链接的结论标为推断。
- 样本不足时明确说「样本只有 N 本，不足以代表整个榜单」。
- 平台数据缺失、页面改版、需要登录时直接说明，并给出替代方案（换公开榜单、作者粘贴页面、只看作品页可见信息）。
- 不做「这本书一定能火」一类预测；只说明当前可见的模式与风险。
