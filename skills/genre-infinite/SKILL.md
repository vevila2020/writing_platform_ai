# 无限流 / 副本流

这张卡只补题材差异。通用结构、场景、人物判断仍按 `novel-craft`。

## 读者承诺

读者要的是**在规则明确、失败真实的副本里靠判断和团队活下来**。

- 核心快感：读规则、找漏洞、分工、牺牲、结算变强。
- 两个空间必须分开：结算/兑换的据点（Hub）与执行任务的副本（Run）。
- 作者要先回答：失败的代价是什么？如果死亡可以无痛重来，紧张感就不存在。

## 核心循环

```text
进入副本（契约、目标、时限、规则）
→ 侦察与分工（谁负责什么、谁不可信）
→ 规则冲突与意外（队友失误、隐藏支线、敌人变招）
→ 关键抉择（救人还是完成任务、用底牌还是留后手）
→ 结算（奖励、伤势、带回物、评价）
→ 据点休整与兑换，新矛盾出现
```

## 开篇（前三章）

1. **第一章**：直接进副本或直接收到契约，让读者立刻知道规则与失败代价。不要在第一章解释主神空间的全部设定。
2. **第二章**：展示一次团队协作和一次判断失误，让读者明白"会死人"。
3. **第三章**：结算并展示兑换，让读者看到成长路径，同时埋下下一个副本的钩子。
4. 开篇避免：主角开局全知、队友全是工具人、规则只在需要时出现。

## 副本设计

每个副本至少写清：

| 项目 | 问题 |
| --- | --- |
| 入口 | 怎么进、能否拒绝 |
| 目标 | 主线任务是什么、怎样算完成 |
| 规则 | 禁止什么、违反的惩罚 |
| 时限 | 有没有倒计时、超时怎样 |
| 队伍 | 谁被分到一起、彼此知道多少 |
| 支线 | 额外奖励与额外风险 |
| 出口 | 怎么离开、要付出什么 |
| 结算 | 奖励、评价、带回物 |

副本之间要有变化：不要每个副本都是"打怪 + 找钥匙"。

## 爽点与钩子

- 优先用"规则被利用"型爽点：主角用一条别人忽略的条款翻盘。
- 团队高光要分配：情报、后勤、战斗、谈判各有人发挥。
- 章尾钩子常用：规则追加、队友背叛、隐藏目标出现、结算异常、据点被袭击。
- 兑换要有取舍：强化哪一项，就意味着放弃另一项。

## 人物与关系

- 团队要有明确分工和信任问题；谁掌握信息、谁有私心，要提前埋。
- 老队员不是保姆，新队员不是拖累道具，双方都要有自己的生存逻辑。
- 主神/系统不要抢戏：它发布规则，但不替主角做判断。
- 死亡要有后果：关系断裂、资源损失、队伍重组，不能只是扣分。

## 常见失效

- 副本像普通地牢，没有契约、规则和时限。
- 没有真实失败，主角光环过于明显。
- 队友只在需要时出现，平时没有生活。
- 奖励点通胀，兑换失去意义。
- 系统话太多，替主角解释一切。
- 每个副本结构一样，读者很快疲劳。

## 动笔前确认

1. 这个副本的规则和失败代价是什么？读者清楚吗？
2. 团队分工是什么？谁可能出问题？
3. 主角的关键判断来自哪条前文信息？
4. 结算改变了什么？下一副本的钩子是什么？
5. 有没有让读者看见"下一次会更难"？
