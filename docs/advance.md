# Advance

Advance 是长篇写作流程，选择器名称为 `Advance`，Skill ID 保持 `novel-serial`。默认选择沿用原有用户设置 `writing_skill_default` 与延迟保存机制；不增加全局模式或另一套运行时配置。底账和作者约束各自归属当前书籍。

## 三个阶段的实现

1. 补齐写前细纲、技法路由、只读审稿与确定性检查；规划侧栏能展示逐章细纲和章组计划。作者本轮字数范围优先于旧目标，缺核心字段或保留占位的细纲不能进入正文。
2. 通过 `prepare_advance` / `commit_advance` 提交最终正文对应的连续性，复用工作区变更组、前镜像、崩溃恢复和撤销。正文、细纲或底账变化时拒绝旧凭据；相同成功请求重试不重复追加。
3. 开书按方向、核心设定、卷/章组、眼前细纲推进；按任务召回技法、研究与已确认作者偏好。复用现有 `novel-craft`、题材 Skill、研究报告和 `CREATOR.md`。

## 章节闭环

细纲检查 → 准备当前事实 → 读取相关材料 → 写正文 → 确定性检查与只读审稿 → 修订 → 再准备 → 提交连续性 → 读回。

默认“继续写”交付下一章；明确的多章范围串行执行，每章提交成功后进入下一章，不设置固定修订轮数或总运行时长。已有授权不反复索取，重大未定剧情才需要作者选择。委派可用时使用实际宿主协议审稿；不可用时明确采用自审。

## 数据职责

| 位置 | 职责 |
| --- | --- |
| `CREATOR.md` | 作者确认的本书长期约束与偏好 |
| `setting/outline.md`、`setting/chapter-groups/` | 未来结构、卷承诺与眼前章组职责 |
| `setting/chapter-plans/` | 一章一份的具体事件、情绪、选择、信息边界、钩子与字数预算 |
| Lore | 稳定身份、规则、关系与能力边界 |
| `setting/continuity.json` | 当前事实、章节正文/细纲版本、摘要、完整人物/伏笔/信息边界记录、未决冲突与活跃集合 |
| `setting/progress.md`、`setting/character-states.md`、`setting/tracking.md` | 从底账生成的阅读视图，不由 Agent 分别手工更新 |
| `setting/research/` | 带来源、日期和适用限制的参考研究，不作为故事事实 |

底账是书籍内容，不是 Agent 执行恢复日志。会话恢复仍使用原有 Product Session journal；Native 与外部运行时的接入位于应用层。

## 提交与修订

`prepare_advance` 返回最终提交必须携带的 `base_revision`，以及活跃人物、伏笔、作者真相与读者所知、近三章摘要、未提交正文和被手工改过的视图。

`commit_advance` 提交实际语义变化：受影响记录按稳定名字/ID 更新；当前工作集合整体替换；移除有效约束、风险或承诺要解释原项怎样被解决或取代。未来计划不能登记成已经发生，作者真相不能直接复制进读者或角色知识。

提交重新检查正文与细纲，并对读取版本进行校验。四个文件通过同一持久变更组写入，保留覆盖前内容。中断后在版本未改变时完成写入；若外部修改使输入失效则显式冲突，保留作者修改，重新准备与核对。外部编辑器的多文件可见性不承诺瞬时切换，完成状态以事务回执为准。

改稿即使只改措辞也要更新正文检查点。改旧章时当前处境保持在已写进展的末端；受影响的后文列入 `unresolved`，解决前阻止新章追加。撤销或恢复书籍版本后重新准备，不假定旧会话里的提交仍有效。

## 已有书稿

首次启用时，先读实际正文和已有进度/人物/台账，再用 `action=initialize` 采纳稿件顺序中的最新章与确认过的当前事实。所有已有非空正文记录版本；原进度作为历史基线保留，原三个视图的内容保存在工作区变更历史中，可整组撤销。初始化不要求补全旧书每章细纲，也不自动改写旧正文。

后续修订导入的历史章需要提供仍完整有效的 `baseline_progress`，纯表达修改可原样保留。已绑定路径不因改标题自动重命名；若通过文件操作删除或移动章节，必须先恢复或核对这些路径变化，不能绕过未提交提示继续写。

## 容量与配置

不新增必填配置。写作检查能力控制 `check_writing` 与 `prepare_advance`；`commit_advance` 同时要求工作区写入能力。Advance 写入门禁只作用于选中的 `novel-serial`，其他写作流程不被强制采用底账。

台账最多 12 KiB；活跃人物/伏笔/信息边界分别最多 20/8/12，完整记录保留。单人物最多 8 KiB，单伏笔与信息边界最多 4 KiB，章节摘要最多 3 KiB；生成进度和人物视图各最多 2 MiB，底账最多 16 MiB，准备源文件合计最多 64 MiB。超限显式整理，不任意截断。

准备结果受现有工具结果预算限制，默认 128 KiB；超限会明确返回 `context_omitted`、底账来源、冲突数量和有效凭据，要求分段读取完整事实后缩小工作集合。具体任务材料预算见 [上下文召回规范](../skills/novel-serial/references/context-and-recall.md)。

## 验证边界

确定性检查负责结构、字数、截断、占位、复读与工程文本等可核验问题；语义审稿负责因果、信息边界、人物选择、期待与兑现。版本和事务检查能验证提交对应的文件，不能替代模型对故事质量或事实提取的判断。工具缺失或提交失败时只能报告草稿，不能报告章节已经完成。
